For agents

How LLM tools should read, and carefully write, a notion-sync workspace.

Two sources​

  • AGENTS.md in the workspace root — generated by the installed binary, so it always matches that version. Read it first when working inside a synced folder. It's tool-owned: don't edit it.
  • This site — the full docs for the latest release. Machine-readable copies: llms.txt (index) and llms-full.txt (everything in one file). Every page is also served as .md.

If the two disagree, AGENTS.md describes the binary that actually wrote the files.

Reading a workspace​

  • Layout and filenames: Workspace layout
  • Frontmatter keys and property types: Frontmatter
  • Treat notion-deleted: true files as historical: Soft deletes
  • File URLs are stable identifiers but won't download: File URLs

Pushing — default to NOT pushing​

push mutates the user's live Notion workspace. Every condition below must hold before you push. If any fails, don't push — stop and report the blocker and its fix to the human.

  1. Explicit human authorization — push only when a human asked, for this specific change. Never on your own initiative.
  2. Workspace in sync — run refresh first and resolve any conflict at the source.
  3. Reviewed dry run — run push --dry-run, show the human what would change, and get their OK.
  4. Validation gate clean — no halt-class files. A halt means stop and report, not force through.
  5. Human consent to the write — the confirmation gate is that checkpoint.

Never silence a guardrail to make a push succeed. --force, --allow-new-options, and a reflexive --yes all suppress protections for the user's data — use them only on explicit, per-run human instruction. Treat cancelled as "ask the human", not "retry with --yes". On any halted, partial, or cancelled outcome, report the entry's reason and fix and stop.

The same rules cover creating rows (notion-create: true). A create-pending halt is never yours to clear: don't flip pending back to true — hand it to the human (see Duplicate guard).
