Frontmatter

Metadata keys and how Notion properties map to YAML.

Every .md file starts with YAML frontmatter. The first block is always notion-sync metadata; everything after is the Notion page's properties.

---
notion-id: "<page-uuid>"
notion-url: "https://app.notion.com/p/<page-id-32-hex>"
notion-last-edited: "<RFC 3339 — Notion's last_edited_time>"
notion-database-id: "<database-uuid>"   # only present for database entries
# notion-deleted: true                  # only present if the entry was removed in Notion (soft delete)
# notion-last-pushed: "<RFC 3339>"      # only present after a push — when properties were last written back

# ... all Notion properties below ...
Title Property: "Page Name"
Status: "In Progress"
Tags: [a, b, c]
PDF:
  - "https://prod-files-secure.s3.us-west-2.amazonaws.com/<bucket>/<uuid>/file.pdf"
---

Metadata keys​

KeyMeaning
notion-idPage UUID — the file's identity
notion-urlCanonical app.notion.com/p/... URL
notion-last-editedNotion's last_edited_time; refresh skips entries where this matches
notion-database-idParent database (database entries only)
notion-deletedtrue once the entry is removed in Notion
notion-last-pushedWhen push last wrote this row's properties
notion-createHand-written on a new file: true asks push to create the row; pending means a create is in flight or failed — see Creating new rows

Property mapping​

Notion typeFrontmatter valuePushable?

multi_selectarray of option namesyes

checkboxtrue or falseyes
url / email / phone_numberstring or nullyes
relationarray of page IDsyes
peoplearray of names (or IDs as fallback)no — Notion-managed
filesarray of URLs (see File URLs)no — Notion-managed
created_time / last_edited_timeRFC 3339 timestampno — read-only
unique_idPREFIX-N or Nno — read-only
created_by / last_edited_byuser name (or ID as fallback)no — read-only

Skipped (not in frontmatter): formula, rollup, button, verification — they're computed or non-portable.

Soft deletes​

Pages removed from Notion are not deleted from disk on refresh. Instead notion-deleted: true is added to the frontmatter. Treat any file with that key as historical. push never pushes these files.
